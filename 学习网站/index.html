LangChain 与基础

LangChain 五大组件

阶段1 P17

Models / Prompts / Chains / Memory / Tools&Agents

🧩 像一套标准工具箱——Models / Prompts / Chains / Memory / Tools，接口统一，缺哪样自己配。

你项目一一对应：llm.ts / system prompt / agent.ts / memory.ts / tools.ts。框架是这些能力的标准化封装，不是新原理。

LCEL

阶段1 P32-33

用 | 把组件串成管道，靠 Runnable 接口统一

🧩 像乐高积木：每块都有统一的凸点接口，能按任意顺序拼成一条流水线。

所有组件实现 Runnable（invoke/stream/batch），prompt | model | parser 就是一条链。价值是统一了“可组合”的协议。

Chain vs Agent（必考）

阶段1 P31

Chain 是固定流程，Agent 是动态决策

🧩 Chain 是照菜谱做菜（步骤写死）；Agent 是厨师看冰箱自己决定先炒哪个（动态决策）。

Chain 路径写死；Agent 由模型自己决定调哪个工具、调几次。你项目是纯 Agent（for 循环），可直接说“我手写的循环就是 Agent 最小形态”。

Function / Tool Calling

阶段1 P35-36

模型只输出结构化调用请求，执行永远是你的代码

🧩 模型像点菜的客人，只写菜单（工具名 + 参数），厨房（你的代码）负责真做。

模型不执行工具，它输出「工具名 + 参数 JSON」。你 llm.ts 里按 index 拼 tool_calls.arguments 就是这件事的细节。

🧩 像解题时的草稿纸：想一步、写一步、看结果再想，而不是一次性憋出答案。

对应你循环里的“调模型 → 拿 tool_calls → 执行 → 把结果塞回 messages”。

🧩 像给面试官递简历：不是把所有经历都塞进去，而是挑最相关的那几段。

短期（同用户）+ 长期（跨用户相似检索）。比“把所有历史塞进去”更工程化。

🧩 像装修队：项目经理拆活，水电 / 木工 / 油漆各干各的，最后项目经理验收汇总。

把大任务拆给子 Agent，主 Agent 做规划与汇总。对应你的 agent.ts 循环可扩展为编排层。

RAG 原理

RAG 的本质（高手答法）

RAG P01-04

把外部知识引入推理过程的架构

🧩 开卷考试：不背下整本书（不改模型参数），答题时现查资料（检索）再作答。

不改模型参数，推理时检索相关知识，提升准确性/实时性/可追溯性。不是“向量库+大模型”这种流程描述。

什么时候不该用 RAG

RAG P01

知识固定且延迟极敏感 → 微调/长上下文；数据极小 → 直接塞 prompt

🧩 为查一个词去建一座图书馆——数据太少时，检索本身就是过度设计。

几十条数据上检索是过度设计。先判断再上 RAG。

Embedding vs 关键词

阶段3 / RAG P08-11

语义距离 vs 字面重合

🧩 关键词像查字典（字面必须对上）；向量像「意思相近就能认出来」（同义词也能匹配）。

关键词（你的 TF-IDF）同义词/改写就检索不到；向量能召回字面不同但意思近的内容，代价是语义漂移。工程上通常两者都要。

多路召回 vs 混合检索 vs Rerank

RAG P08-11 + P35-36

召回多通道 → 融合排序 → 精排取 Top-K

🧩 招聘：多路召回 = 多个渠道收简历；混合检索 = 把各渠道简历去重合并；Rerank = HR 精读挑出最合适的几个。

多路召回：关键词 BM25 + 向量各召回一批；混合检索：用 RRF 等融合；Rerank：交叉编码器精排（慢但准）。

高级 RAG（预检索）

RAG P26-31

查询转换 / HyDE / 句子窗口 / 层次索引

🧩 问路前先想清楚怎么问：把「那个地方怎么走」改成「从 A 到 B 怎么走」，对方才答得准。

解决用户问法与知识库表述不一致、语义割裂的问题。你的“杀手锏”多路召回就在这里。

检索与向量

向量相似度

RAG P37 / 黑马 P20-21

余弦 / 欧氏 / 点积，适用场景不同

🧩 余弦像比较两人「关注方向」是否一致（不看嗓门大小）；点积还看嗓门（向量长度）。

余弦对向量长度不敏感，最常用；点积受长度影响大；欧氏是几何距离。选错度量方法检索质量会掉。

向量索引

RAG P37-38

HNSW / IVF / Flat / LSH

🧩 图书馆索引卡：HNSW 按主题连成关系网（顺网找最快）；IVF 先按大类分柜再翻（适合海量）。

HNSW（图，快，内存高）是默认；IVF 先聚类适合超大规模；Flat 暴力精确但慢。

向量数据库选型

RAG P39-40

Chroma / pgvector / Milvus / Qdrant

🧩 选交通工具：Chroma 是自行车（本地随手用）；pgvector 是已有的家用车（不添新东西）；Milvus / Qdrant 是货车（数据量大才需要）。

Chroma 本地开箱即用；pgvector 已有 Postgres 少引入组件；Milvus/Qdrant 数据量大要生产级扩展。

评估

Evals（高频挂点）

RAG P41 / test/

断言（确定性）+ 黄金问题集（非确定性）

🧩 给 agent 做体检：确定性指标是量血压（硬数值）；黄金集是模拟考（看综合表现）。

面试官问“你怎么知道 agent 改好了还是改坏了”：确定性用断言（你 142 条），非确定性用黄金集跑命中率与回归。

RAG 评估指标

RAG P41

检索侧 Recall@K/MRR；生成侧忠实度/相关性/正确性

🧩 检索侧看「资料找全没」（Recall / MRR）；生成侧看「有没有瞎编」（忠实度）。

工具 RAGAs、TruLens。忠实度（faithfulness）看有没有编；相关性看答非所问。

LangGraph

LangGraph vs LangChain

尚硅谷 P08-12

组件库+链式编排 vs 显式状态机

🧩 LangChain 是造零件的车间；LangGraph 是画流程的施工图（零件怎么流转）。

LangChain 管“单个链怎么搭”，LangGraph 管“多个步骤怎么流转”（StateGraph：节点+边+条件分支+循环）。

StateGraph

尚硅谷 P28-47

节点 + 边 + 条件分支 + 循环

🧩 像地铁线路图：节点是站，边是轨道，条件分支是换乘，循环是环线。

把流程建模成图，适合回退/分支/多 Agent 协作。你的 for 循环是它的最小特例。

四种图设计模式

尚硅谷 P128-132

提示词链 / 路由 / 编排器-工作者 / 评估器-优化器

🧩 四种常见流水线：一条道走到底（提示词链）、岔路口选路（路由）、包工头派活（编排器-工作者）、先做再改（评估器-优化器）。

多 Agent 协作的标准范式，面试能说出名字+区别就是加分项。

持久化 / 检查点

尚硅谷 P56-60

可恢复执行 ↔ 你的 memory.ts

🧩 像游戏存档：打不过可以读档重来，不用从头开始。

“可恢复执行”是什么——中断后能从中断点继续。对应你落盘的会话状态。

后端 / FastAPI

同步 vs 异步 / WSGI vs ASGI

阶段2 P01/P04

AI 后端为什么必须异步

🧩 同步像排队打饭（一个人打完下一个才能上）；异步像取号等叫（等的时候能先干别的）。

模型推理是 IO 密集，异步才能高并发。对应你 Node 单线程事件循环的设计。

阶段2 P12-14

声明式数据校验

🧩 像门口的安检机：格式不对的请求直接拦下，不让它进到业务代码里。

FastAPI 用 Pydantic 校验请求体；你 server.ts 里手工写校验，可对照迁移。
